gridline

private · working codename

An energy-market simulator built to stand in for PLEXOS, with two differences. It is visual-first: you design the system on a schematic canvas or a map and read the results on that same network, not in property tables. nem-ingestion

private

The pipeline both dashboards read from: six NEMWEB clients on a five-minute worker covering dispatch prices, SCADA generation, price setter, bids, PASA, and generator metadata. It is the only process that writes to Postgres and the sole owner of the schema across 13 tables, which is what lets the two apps above be read-only. Backfill CLIs handle cold starts and gap repair, hourly rollups serve the long display windows, and a retention sweep took the database from 21 GB to 2 GB — most of the hosting bill was Postgres memory.

pocket-etrm

private

A local-first Energy Trading and Risk Management app for a NEM trading desk, built as a native phone app. Capture ASX futures and caps across NSW, QLD, VIC and SA, bespoke OTC contracts with custom month, day-of-week and hour-window delivery shapes, and LGC and ACCU certificates. Then see netted positions with mark-to-market, daily and closed-out P&L, hour-weighted MWh exposure, limit breaches, and a parametric delta-normal VaR with editable vol and correlation assumptions. A "Sync ASX" action reads the public ASX Energy settlement pages straight from the phone, and every mark is tagged ASX, manual or synthetic so it is always clear which numbers are real.

Nothing derived is stored: positions, MtM, P&L, exposure and VaR are all computed on read from deals and marks, so every number on screen traces back to the ticket that produced it, and a new valuation rule never needs a backfill. One function, unitHours(type, tenor), decides how many hours or certificates an instrument spans, and every valuation is written once against it, which is why adding certificates as a second commodity changed that function and nothing else. Shipped as thirteen tagged releases, v0.1 to v1.3, over the air with EAS Update.

TypeScript · Expo / React Native · SQLite · Drizzle ORM · Jest · EAS · 105 tests on a pure calc engine

agent-tui public

github.com/tder311/agent-tui →

A terminal control room for local AI coding agents: one tree of every project on the machine, with its git worktrees, branches, historical Claude Code and OpenCode sessions, the agents running right now, and open GitHub PRs. Sessions carry real titles instead of raw UUIDs, live agents get a busy/idle/blocked status dot, and o opens anything — resume a session, open a worktree in a new terminal tab, or jump to a PR in the browser.

Discovery is app-agnostic: rather than hardcoding where each tool puts its worktrees, it sweeps the filesystem for the .git markers git itself uses, so anything git considers a worktree is found no matter which app created it — Claude Code, Conductor, OpenCode, or something unregistered. Clones of the same upstream are folded into one project by normalised origin URL. Scanning is read-only and runs off the UI thread; the only mutations are explicit worktree/branch deletes and prunes, each behind a y/n confirm.

Go · Bubble Tea · Lip Gloss · ~4,900 lines · 57 tests · MIT · go install

railway-tui public

github.com/tder311/railway-tui →

A terminal dashboard for Railway: one static binary that logs in over OAuth and gives a live view of every project, service, deployment, log stream, and environment variable — and restarts, redeploys, rolls back, stops, or cancels a deployment without leaving the terminal. Runtime, build, HTTP, and environment-wide log modes with live filtering; variables masked by default, revealed with r and copied over OSC52. Railway exposes no REST API for any of this, so it all runs over GraphQL, authenticated by an Authorization Code + PKCE flow with dynamic client registration and silent token refresh.

Polling has to be frugal: a Hobby token allows roughly one request every 3.6 seconds, so each refresh is a single batched query, intervals are staggered per resource, and a 429 backs off exponentially. Every side effect is a Bubble Tea command returning a message — no goroutine touches UI state — which is what makes the model tree testable without a terminal.

Go · Bubble Tea · Lip Gloss · Railway GraphQL API · OAuth 2.0 PKCE · 4,400 lines · MIT · go install · goreleaser + GitHub Actions release pipeline

work-graph

private

A local, git-backed work tracker that people and AI agents share: what's left, who has it, and what each task waits on. YAML files are the source of truth, and one Python core drives a CLI, a local web page and a Textual terminal UI. Ready and Blocked are derived from the dependency graph rather than stored, the longest remaining chain is highlighted, and priority flows backwards, so whatever stands in the way of P1 work is treated as P1 too. Agents run workgraph next before asking what to do, and merged or closed PRs close their tasks automatically.

Every edit, from any view, agent or PR sync, is its own commit, and a write fetches, merges and pushes before it reports OK, so two machines can work the same graph at once. A custom git merge driver merges concurrent edits task by task, and status changes are compare-and-swap: if two clones claim the same task, the second write fails and says who won.

Python · Typer · Textual · FastAPI · ruamel.yaml · git merge driver · 400+ tests
